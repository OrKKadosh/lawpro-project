**Conflict-resolution / clustering audit** (prompted by a direct question about whether extraction quality itself should be improved, not just the summarizer comparison): inspected the real conflict output from both cases' extraction runs (`runs/candidate_timelines/*.json`) rather than assuming `conflict.py`'s unit tests were representative of real behavior.

**Second real bug found in the fresh output — salience/compression, not clustering** (`evalkit/extraction/salience.py`, `DECISIONS.md`): the same class of problem as the clustering fix, one stage downstream. Routine-event compression grouped purely by `(type, provider)`; 36 Davis medication-type events shared `provider: None`, so every distinct drug given during the hospital stay fell into one bucket and got compressed to essentially first+last regardless of which drug — Cefazolin, for example, disappeared from the final timeline entirely despite 7 real, correctly-clustered candidate mentions.
- Fixed in two corrected passes, both verified against real data before trusting them (not shipped on the first attempt that looked plausible): a first fix (reusing `cluster.py`'s per-field distinctness check inside one fuzzy union-find pass) looked right in isolation but real-data testing caught it silently reintroducing contamination through a different path — a compound "transitioned to Oxycodone and Gabapentin" candidate bridged the two drugs (and several more) into one 26-member group via union-find's transitive closure, since a pairwise "not distinct" veto isn't actually a transitive relation. A second fix (exact-key grouping for `medication`/`procedure`/`diagnosis_or_finding` together, fuzzy only for `concept`-only events) closed that hole but broke something else: real PT-visit candidates commonly populate `procedure` with descriptive text worded differently mention to mention, so exact-keying on it fragmented real therapy courses into near-singletons instead of compressing them.
- Final design: only `medication` (confirmed to be short, specific, and consistently worded across real repeated mentions) gets exact-key grouping; `concept`/`procedure`/`diagnosis_or_finding` are pooled into the fuzzy word-overlap tier, restoring correct PT-course compression. Verified against real data: final medication sub-group sizes went from one broken 26-member group to a correct max of 10 (per-drug); therapy sub-group sizes correctly returned to full per-provider courses (63, 58) after the intermediate broken fix had fragmented them. Two new regression tests added.

**Root cause of the Harrison/X-ray fabrication (above), investigated -- two attempted fixes to `evalkit/extraction/cluster.py`'s `facts_clearly_distinct()`, BOTH tried and reverted after real-data testing found each unsafe. Shipped code is UNCHANGED from before this investigation.**

This is worth recording in full, including the two wrong turns, because both looked correct after a normal unit-test pass and only broke under real-data verification -- exactly the discipline this project has tried to hold itself to throughout (`ERRORS.md`'s pattern: verify claims for real, don't just assert them from reading code).

- A fresh-context `code-reviewer` pass traced *why* the Harrison duplicate survives instead of merging into the correctly-attributed Finch X-ray event: `facts_clearly_distinct()` checks name fields in order (`concept`, `diagnosis_or_finding`, `procedure`, `medication`) and returns "distinct" as soon as it finds ANY populated-and-disagreeing field pair -- `concept` disagrees here ("imaging study" vs. "X-ray cervical spine (prior)", no shared words), so it returns True without it mattering that `procedure` ("X-ray cervical spine, three-view series" vs. "X-ray") would have agreed. Confirmed directly against the real cached candidates (`runs/candidate_timelines/case-vance.json`, 337 candidates, $0 cost).
- **Attempt 1, reverted**: reorder `NAME_FIELDS` most-specific-first and decide only on the first field both candidates populate, rather than scanning every field for any disagreement. This unblocks the Harrison/Finch merge in isolation (verified) -- but a SECOND fresh-context `code-reviewer` pass, testing the change against the full real cached candidate set end-to-end (not just the intended fixture), found it silently dropped a `materiality="high"` billing event (an Anesthesia line, CPT 01402) from case-vance's actual final timeline: two genuinely different billed procedures' `procedure` fields shared only the boilerplate token "CPT", registered as "agreeing" at that now-highest-priority field, and the function stopped there -- never reaching the genuinely-disagreeing `diagnosis_or_finding`/`concept` fields that the ORIGINAL check-everything logic would have caught. ~16 case-vance and 4 case-davis real cluster groups were affected by this change, several as genuine over-merges (CPT-97110-vs-97140 PT modality pairs, a 3-way lab-panel conflation). An earlier hand-check of "every changed event" by the author of this fix (not the reviewer) missed this -- the failure was spread across many date-groups and only surfaced by systematically diffing cluster membership against the pre-fix code and tracing changed clusters all the way to the projected timeline, not by spot-checking a handful of examples. **Reverted.**
- **Attempt 2, reverted**: making field-agreement actively FORCE a merge (not just stop blocking one), since even attempt 1's reordering alone didn't merge Harrison/Finch -- their overall text Jaccard (~0.12-0.18) never clears `SIMILARITY_THRESHOLD=0.25`. Tested for real against case-vance's full cached candidates: collapsed the final timeline from 202 to 137 events (a third of it gone) -- the same boilerplate-token-as-false-agreement problem, at corpus scale. **Reverted.**
- **Net effect: `facts_clearly_distinct()` and `NAME_FIELDS` ship exactly as they were before this investigation began** -- confirmed by re-running the deterministic pipeline stages (cluster → conflict → canonicalize → salience → project) on both cases' cached candidates and diffing against the frozen files: exact match, `case-vance` 315 clusters/202 final events, `case-davis` 170 clusters/140 final events, both unchanged, 0 schema-validation problems. `runs/candidate_timelines/*.json`/`results/timeline_eval/*.json`/`results/pipeline_demo_*.json` needed no reconciliation since nothing about their generation changed.
- **The Harrison/X-ray fabrication remains genuinely unresolved.** A real fix needs boilerplate/generic tokens (bare CPT-code prefixes like "CPT", category words like "urine drug screen") excluded from the word-overlap comparison used by `facts_clearly_distinct()`, likely combined with removing the unreliable, loosely-worded `concept` field from consideration entirely -- a larger, more carefully-tested redesign (with its own dedicated dev-set-style verification, mirroring the chunking/prompt-experiment methodology) than this session's remaining time/budget supported doing safely. Documented here as an honest, disclosed limitation rather than shipped as a half-verified fix.
